# scheduler 是普通实例，不提供全局单例

`scheduler` 通过构造函数拿到 engine 数量与放置策略，由使用者（`main`、测试夹具）持有。最初想做成全局单例（"任何地方都能 submit"），最终放弃：测试需要同时存在两个互不干扰的 scheduler，各自拥有线程池，单例会让这类测试只能串行、且失败表现为偶发。便利性交给可选的全局访问点（如果将来真的需要），但类的构造路径不被收窄。

## Considered Options

- 全局单例：省掉传递引用的麻烦，但把"一个进程只有一套线程池"写进了类型系统，测试与嵌入场景直接受限。
- `thread_local` 的 current engine 指针：回答"我现在跑在哪个 engine 上"，不承担"找到全局调度器"的职责，两者职责不重叠。

## Consequences

- 所有需要调度的代码必须显式拿到 scheduler 或 engine 引用（构造注入或参数传递）。
- 若以后加全局访问点，它必须是可选的薄封装，不能成为唯一构造路径。
